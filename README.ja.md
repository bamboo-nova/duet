# duet

[English](./README.md) | **日本語**

Claude Code(cc)と Codex(cx)を役割固定の開発デュオにするプラグイン。片方が計画とレビュー、もう片方が検証と実装を担う。単一のコードベースで Claude Code と Codex CLI の両方で動く。

※ 英語版 [README.md](./README.md) が正規のドキュメントです。差異があれば英語版を優先してください。

## 構成図

構成図(コンポーネント棚卸し・実行フロー・代表トレース)は Excalidraw 図として管理している。[`docs/out/duet-ja.excalidraw`](./docs/out/duet-ja.excalidraw) を [excalidraw.com](https://excalidraw.com) で開いて閲覧できる。図の元となる正規レコードは [`docs/structures/structure-duet-ja.yaml`](./docs/structures/structure-duet-ja.yaml) で、構造の変更はこの YAML の diff としてレビューできる。

```mermaid
flowchart LR
    U([ユーザー]) --> I[フェーズ1<br/>要件確定インタビュー]
    I -->|ゲート①承認| P[フェーズ2<br/>cc: 計画+サブゴール分解]
    P --> V[フェーズ3<br/>cx: 検証ループ ≤3]
    V -->|指摘| P
    V -->|ゲート②承認| A[フェーズ4<br/>ADR 書き出し]
    A --> IM[フェーズ5<br/>cx 実装 / cc レビュー ≤3]
    IM --> R[フェーズ6<br/>完了報告]
```

## なぜ役割固定か

- cc(Claude Code)は計画立案・サブゴール分解と、実装コードのレビューを担う。
- cx(Codex)は計画の検証(穴探し)と実装を担う。
- 起動元 CLI はオーケストレーションと要件確定インタビューを担う。

cx は目的が曖昧だと勝手に推論してゴールを作る。そこで最初に要件をインタビューで固定し、文書にしてから渡す。さらに、計画を立てるモデルと検証するモデルが別物であるため、検証ループが「自己採点」ではなく本当のクロスチェックになる。

## パイプライン

1. 要件確定インタビュー → `requirements.md` → ユーザー承認
2. cc が計画立案・サブゴール分解 → `plan.md`
3. cx が計画を検証(サブゴール個別 + 全体整合性)。high 指摘ゼロまたは3ループで収束 → ユーザー承認
4. 収束した計画を `adr-*.md` として書き出し
5. サブゴール単位で cx が実装し、cc がレビュー。不合格は同一セッションで修正(最大3回)
6. 完了報告

状態は対象リポジトリの `.duet/` に保存され、中断しても途中から再開できる。

## 前提条件

- `claude` と `codex` の両 CLI がインストール済みであること。
- 各 CLI の config で既定モデルを設定しておくこと。プラグインはモデルを指定しない。検証・実装には強いモデルを推奨する。
- codex-cli は 0.151 系で動作確認。
- 動作検証は Claude(Fable 5)と GPT(Sol)を既定モデルとして実施した。Astra や Fable 5.1 など別のモデルでは、挙動が異なりうる。

## インストール

Claude Code:

```
/plugin marketplace add <このリポジトリのパス>
/plugin install duet@duet
```

Codex CLI:

```
codex plugin marketplace add <このリポジトリのパス>
codex plugin add duet@duet
```

## 使い方

対象リポジトリで次を実行する。

```
/duet ログイン機能を追加したい
```

引数なしで実行すると `.duet/state.json` から再開する。Codex では duet スキルを直接呼び出す。

## Tips: grilling 系スキルとの併用

アイデアを詰問形式で鍛えるスキル(例: mattpocock-skills の `grilling`)と duet は相性がよい。フェーズ1の前後で grilling を走らせると、厳しい質問に対話で答えた内容がそのまま要件と計画のサブセクションになる。フェーズ3では、その各サブセクションに cx の検証ループがかかる。人間による詰問とモデル間検証の二段構えになるため、抜け漏れが出にくく、文書も整理される。

## herdr 連携(任意)

[herdr](https://herdr.dev) のペイン内で duet を起動すると、人間を待つ地点(承認ゲート・エスカレーション・完了)でデスクトップ通知が届く。`HERDR_ENV=1` を自動判定するので設定は不要。herdr の外では通知は出ず、動作も変わらない。

放置運用の例: herdr で個室(worktree)を作り、その中で `/duet` を起動して別の作業に戻る。承認が必要になると通知が光るので、確認して先へ進める。

## 安全上の注意

- プラグインは git 操作(add / commit / branch / worktree)をしない。コミットはユーザーが行う。
- cx の実装は workspace-write サンドボックスで行い、書き込みは対象リポジトリ内に限られる。ネットワークは依存追加のため許可している。
